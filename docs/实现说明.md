# 实现说明 — #1517 知识分类与元数据

## 需求还原

企业知识库与多 Agent 协作系统（系列 50 单）的拆单之一。本单范围：
**设计八类知识库的分类、元数据与来源追踪规范**。

验收标准：**提交 taxonomy、schema 与样例校验**——即：
1. taxonomy（八类分类法，证明"分得清"）；
2. schema（元数据规范，证明"记得住"）；
3. 样例校验（8 类样例 + 非法被拒，证明"可执行"）。

## 设计

### 1. taxonomy 八类

| 类别 id | 名称 | 编码 | 关联系列单 |
|---|---|---|---|
| agent_role | 角色规范 | AR | #1489 角色卡 |
| methodology | 流程方法论 | ME | #1508 方法论接线 |
| case_study | 案例复盘 | CS | 案例库类 |
| template | 模板范本 | TP | FDE 交付手册 |
| standard | 标准规范 | ST | 合规边界 |
| reference_data | 参考数据 | RD | 数据类 |
| evidence | 证据台账 | EV | #1523 证据台账 |
| faq | FAQ 问答 | FQ | 整合沉淀 |

选择依据：覆盖企业知识库八种典型形态（身份/流程/案例/模板/规范/
数据/证据/问答），且与系列 50 单已有/将有的交付物一一对应——taxonomy
不是空想分类，而是从真实交付物反推的落地分类。

### 2. schema（元数据规范 + 来源追踪）

- **统一基座**：entry_id / knowledge_type（八类枚举）/ title / status /
  owner_role / created_at / version / source_trace
- **来源追踪**（验收要求"来源追踪规范"的核心落点）：
  `source_trace = {origin, provenance[], classification_reason}`
  - origin ∈ {internal_project, public_reference, customer_material, synthesized}
  - provenance = 引用清单 {source_id, reference, accessed_at, excerpt}
  - customer_material 必须带 classification_reason（授权理由）
- **类型专属扩展**：`type_specific` 对象放各类专属字段（如
  agent_role 的 bot_id/domain/escalation）

### 3. 样例校验（可执行证明）

8 个合法样例各归一类（kb-ar-* 到 kb-fq-*），1 个反例包含
未知类型/缺字段/额外字段/空来源，校验器全部拒绝。

`load_dir()` 按文件名（kb-*.json，跳过 invalid）批量加载并校验，
返回 (合法数, 拒绝列表)——买家可一键得到"8 过 0 拒"。

### 4. 合规红线

对齐原文"只能使用获授权或脱敏的资料"：`customer_material` 无授权理由
直接拒绝（测试 11）——这不是提示而是**硬校验**。

## 与系列其他单的关系

- taxonomy 直接反哺后续知识类单：分类法让每条知识有确定归属；
- 元数据统一基座让多 Agent 能按 knowledge_type 检索不同类知识；
- 来源追踪让"引用可回链"有规范支撑（与 #1508 的 citations 呼应）。
